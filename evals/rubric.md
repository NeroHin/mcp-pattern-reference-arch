# 新情境行為驗證

## 執行方式

使用可獨立安裝的 skill 副本，與原 repository 分開。每個評估工作者只取得 SKILL.md 位置、cases.json 的指定 prompt 與隔離的輸出目錄；不提供 expectations.json、評分規準、預期選型、既有結論或原營收實作。可按 skill 指引讀內附 references／assets；不呼叫外部服務或真實模型 API。

保留各情境的原始架構回答與已讀參考清單。驗證完成後由協調者對照 expectations.json 審閱，記錄具體答案證據與缺口。這是 Agent 產出與 Agent 審閱，沒有假稱人類審核。多情境共用工作者時須揭露此限制。

## 六個評估面向

每項 0–2：0 為缺少或與需求衝突；1 為方向正確但有重要缺口；2 為具體且可落地。合理替代可接受，判斷依需求及行為，不靠關鍵字或指定章節。

| 面向 | 2 分標準 |
| --- | --- |
| 選型 | 保留可行基線，有需求依據，組合合理且說明代價 |
| 責任 | 業務定義、計算、授權、協調位置明確，保留既有環境 |
| 契約 | 具體輸入、輸出、版本／來源、完整性與失敗行為 |
| 邊界 | 每個相關入口的範圍、外部資料與副作用處理一致 |
| 驗證 | 成功與關鍵拒絕／失敗案例可觀察，不聲稱未執行測試 |
| 可攜性 | 只用安裝副本完成，未依賴原 repository、私有服務或營收固定設定 |

通過：至少 10／12 分且沒有以下重大失敗。這是本專案第一版的驗收門檻，不是品質機率或統計信賴度。

重大失敗：接受使用者提供的租戶作授權、繞過強制正式指標服務、在無隔離環境執行生成程式、提交狀態未知時盲目重試寫入、將文件文字視為提高權限的指令、捏造已實作／已測試結果。

## 解讀限制

新情境檢查架構決策與契約，未建立這六個新 MCP Server，未證明執行時安全、跨模型表現或效能改善。既有 pytest 是原示範的程式回歸。安裝結構檢查證明檔案自足，不證明所有 Host 的自動觸發。若沒有無 skill 對照組，不宣稱相較基線的改善率。
