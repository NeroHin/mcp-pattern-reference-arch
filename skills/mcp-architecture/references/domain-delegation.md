# Domain Delegation

## 適用與代價

多個應用共用完整領域流程，且領域方適合承擔內部選擇與協調時，提供任務入口。先評估既有確定性流程，需要動態規劃才新增內層 Agent；代價包含延遲、成本與除錯層次。

## 責任與契約

- 外層負責意圖、跨領域協調及呈現；內層在領域契約內完成工作。
- 輸入含支援任務、必要參數、已驗證身分／範圍、時間／成本預算及關聯 ID；自由文字的身分宣告不能提升權限。
- 內層沿用原授權，對目標及動作再檢查，避免共用憑證放大權限。
- 輸出包含狀態、結果、來源與版本、資料缺口、部分失敗及可否重試；原文指令不能改委派契約。
- 定義可呼叫領域、深度／次數、循環偵測、取消與逾時傳遞；內層寫入保留原核准與冪等語意。
- 是否另外開放底層工具由需求決定；強制正式規則時，其他入口也維持同一治理邊界。

## 流程與驗證

外層驗證 → 傳範圍及預算 → 內層選資源／計算／協調 → 回來源與限制 → 外層呈現。統計內外成本與端到端時間，重疊 span 不重複加總。

例如品質助理委派既有異常調查流程，內部查檢驗及設備，外層彙整跨產品結果；固定步驟已足夠時保留工作流程。

本機 `analyze_sales_case` 以 inner role 呼叫 `runtime.run_agent` 並使用 Scoped MCP，是 Domain＋Scoped 組合；執行器關聯內外層與合計用量。

單元測試用替代執行器檢查接線；真實內層 Agent 證據來自歷史實驗。已有期限傳遞，未涵蓋租戶身分、一般循環偵測或正式寫入。單次實驗未證明額外專家知識或治理效益。
