# Scoped Capabilities

## 適用與代價

任務、角色或資源範圍已知時提供需要的能力。可用靜態註冊，或依可信授權選擇能力。範圍變更、撤權與工具快取需保持一致；限制過窄會阻止合理任務。

## 責任與契約

- Host／Client 提供使用者選定對象；Server 驗證它與可信身分的關係；後端檢查目標資源及動作權限。
- 分別定義「可見工具、可查物件、可執行動作」。隱藏名稱或只讀不能取代授權。
- 以可信設定或已驗證的請求上下文傳範圍；依 transport／版本設計，不假定授權永久綁在連線。
- 搜尋、metadata、直接按 ID 讀取、派送及內層服務都檢查相同邊界。
- 越權錯誤避免揭露其他租戶物件是否存在；空結果與執行失敗可區分。

## 流程與驗證

可信身分＋工作範圍 → 驗證能力 → 驗證物件及動作 → 後端執行 → 過濾欄位與來源。

例如設備維護助理只提供指定設備的狀態與紀錄；使用者傳入設備 ID 仍須驗證存取權。

本機 `servers/scoped/server.py::build_server` 只註冊 `registry.CORE` 四個操作，與 Flat 的核心函式相同。這是靜態集合，沒有角色、租戶與撤權實作。

測試：核心契約與基線相同、無關工具不可見、允許操作仍完成任務。正式整合另測跨租戶 ID、撤權快取、搜尋及派送繞過。完整路徑見實作對照。
