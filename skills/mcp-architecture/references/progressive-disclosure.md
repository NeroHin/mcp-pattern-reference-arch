# Progressive Disclosure

## 適用與代價

資料龐大而每次通常只讀局部時，先定位再取得細節。代價是往返、摘要遺漏、內容更新或 ID 失效。全量數值彙總通常仍需完整數值。

## 責任與契約

- 搜尋在授權範圍內回傳穩定 ID、選擇所需摘要、來源版本與下一頁。
- metadata 提供選擇／理解結構需要的欄位，避免逐筆重複整份 Schema；它是可選階段，有 ID 可直接讀授權內容。
- 內容讀取接受有限批次或區段，檢查物件權限、版本與回傳預算，明示截斷、下一段或資源連結。
- 定義快照、排序、游標與版本衝突行為，避免跨頁重複或遺漏。
- Client 支援 Resources／連結時可用；不支援時以工具回傳受限內容與分頁資訊。

## 流程與驗證

搜尋 → 選 ID／區段 → 必要時讀 metadata → 讀內容 → 引用來源與版本。全量計算使用必要完整欄位或後端彙總，不因縮小回傳而漏資料。

例如研究文件服務先提供相關文件與章節，再讀選定章節；已有章節 ID 可直接取內容。

本機 `backend.search_records` 回 ID／標題，`get_metadata` 回類型、訂單與時間，`get_content` 讀全文；`selected` 的 1–100 個 ID 是範例上限。

測試涵蓋來源保留、metadata 不含客服原文／金額、該批資料比完整內容小。未實作搜尋分頁、快照或通用回傳預算。營收實驗仍讀全部交易，沒有證明一般性 token 改善。
