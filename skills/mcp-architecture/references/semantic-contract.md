# Semantic Contract

## 適用與代價

需要統一定義、單位、時間與彙總規則時，使用可識別且有版本的業務定義。前提是定義與維護者存在；未知指標先確認，模型不能補造正式口徑。

## 責任與契約

- 領域方維護公式、時間語意、排除條件、幣別／單位、粒度、維度與版本。
- 後端計算，Server 驗證指標、期間、維度、授權及預算；Agent 選參數、解釋結果。
- 回傳定義版本、單位、區間／時區、資料時間／版本、粒度與來源。大量來源可提供可追溯查詢 ID／受控證據，避免無限展開。
- 定義空結果、資料延遲、不支援維度、舊版本行為。未完成或截斷結果不能當完整彙總。
- 若正式答案強制來自指標服務，原始工具及內層 Agent 都維持該限制；若允許依相同公式自行計算，明寫此選擇。

## 流程與驗證

確認指標／版本 → 確認維度、區間與範圍 → 後端計算 → 取得來源 → 按需讀原文。

例如設備可用率由維運團隊定義停機、排除維護時間與時區，Agent 不自行用狀態次數猜可用率。新增定義不必一律新增工具，依行為決定。

本機 `backend.METRICS` 定義指標及維度，`query_metrics` 計算淨營收／退款，回定義版本、單位及來源；期間採帶時區的起點包含、終點不包含。

測試核對跨月退款、狀態排除、原始與語意一致，拒絕未知指標／維度。版本固定 v1，未含審核或遷移。所有組都取得相同公式，因此全組答對不能證明降低口徑錯誤；探索仍有重複維度資訊。
